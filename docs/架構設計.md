# 架構設計

## 分層

```
cli.py ─► core/pipeline.py
            │ 1. find_extractor(url)          extractor/
            │ 2. extractor.extract() → MediaJob（純資料，只存 session_id）
            │ 3. 每條串流 protocol_for(kind)(ctx).run()   protocol/
            │ 4. ffmpeg 合併                   postprocess/
            ▼
   ┌──────────── session/ ────────────┐
   │ Session：CookieJar（唯一來源）    │◄── 提取器建立、設定 refresher
   │          headers / proxy          │
   │          refresh() single-flight  │
   └──────────────────────────────────┘
            ▲ 所有請求都透過 Session
   protocol/（HLS / DASH / FILE）── Segment ──► fetcher/（httpx / aria2 / curl / browser）
            │
            └─ backfill/（回溯策略）
```

| 目錄 | 職責 | 不負責 |
|---|---|---|
| `extractor/` | 解析網站、登入、建立 Session、產生 MediaJob、提供 refresh | 下載 |
| `session/` | cookies / headers / proxy 的唯一來源；刷新；瀏覽器同步 | 網站邏輯 |
| `protocol/` | 理解串流格式：播放清單、片段、金鑰、直播輪詢、回溯、本地清單 | 傳輸細節 |
| `fetcher/` | 把一個網址抓成一個檔案；並行限制（全域 / 每主機） | 格式 |
| `backfill/` | 由已知片段推出網址模板，探測更早的片段 | 下載 |
| `core/store.py` | 片段狀態，`backup/{title}/store.json`，斷點續傳 | |

## Session 規則（解決舊版 cookies 反覆抽出注入的問題）

1. **CookieJar 只有一份**。httpx client 直接共用該 jar（不是複製），伺服器的 Set-Cookie 立即生效。
2. 外部工具（aria2、curl、瀏覽器 fetch）需要時才以 `session.headers_for(url)` 產生標頭，依 RFC 規則挑選該網址適用的 cookie，不保存副本。
3. cookie 一律保留 domain / path / secure / expires；舊版只複製 name=value 會送錯網域。
4. `authority`：瀏覽器為權威時只會「瀏覽器 → jar」，`push_to_browser()` 會直接拒絕，避免互相覆蓋。
5. UA 以瀏覽器 `navigator.userAgent` 為準（`attach_browser`），爬蟲與下載的指紋一致。
6. 401/403 → `fetch_with_retry` 呼叫 `session.refresh(seen_version)`；同時失敗的請求只會觸發一次刷新。
7. 多視角需要獨立身分時用 `SessionManager.fork(id)`。
8. proxy 是 Session 欄位，所有 Fetcher 自動套用。

```python
class FooExtractor(InfoExtractor):
    config = ExtractorConfig(name="foo", valid_url_regex=r"foo\.com/live/", priority=10, backfill=False)

    async def extract(self, url, ctx):
        session = ctx.new_session({"Referer": "https://foo.com/"})
        # 需要瀏覽器時：browser = await ctx.new_browser(); await session.attach_browser(browser)
        session.set_refresher(self.refresh)
        ...

    async def refresh(self, session):
        ...  # 重新登入 / 重新取得簽章
```

## 回溯

- `UrlDiffBackfill.build`：比較兩個片段網址，只允許「同一組數字」在一處或多處不同 → `{num}` 模板、補零位數、間距。若有第二組獨立變化（如每段簽章）則放棄。
- 間距 1：分段二分搜尋下界（舊版逐段切片 → 現在約 log2(距離) 次請求）。
- 間距 > 1（時間戳命名）：先試常見間距（舊版 Deltas），失敗再以 1.5 倍間距範圍並行掃描，並學習新間距。
- 啟用回溯時片段的排序鍵為網址中的數字，回溯片段與播放清單片段可直接合併排序。
- 加密且播放清單未給 IV 時，依 RFC 8216 以媒體序號為 IV；本地 `media.m3u8` 每段寫出明確 IV（舊版用全 0，在 MEDIA-SEQUENCE ≠ 0 時會錯）。
- 網站可用 `ExtractorConfig.backfill=False` 關閉（取代舊版 `SKIP_FORMAT_URLS`）。
- DASH：`SegmentTemplate` 本身就是模板，轉成 `UrlTemplate` 後重用 `discover()`，見 `protocol/dash/__init__.py`。

## 停止與續傳

- 第一次 Ctrl+C：停止追蹤直播新片段，完成進行中下載後照常產生清單與合併。
- 第二次 Ctrl+C：強制中斷。
- 重新執行相同指令：讀取 `store.json`，已完成的片段（檔案以 `.part` 寫完才改名，存在即完整）直接略過。

## ZAN-LIVE（`extractor/adapters/zan_live/`）

| 檔案 | 內容 |
|---|---|
| `urls.py` | 網址集中管理（domain 可替換供測試），detail / playroom 網址解析（任意語系前綴） |
| `pages.py` | 純解析：meta → pydantic、參演者、封面、禮物、留言清單、CSRF、選票規則 |
| `auth.py` | httpx 表單登入；失敗或無帳密時以瀏覽器登入（可手動），瀏覽器成為 cookie 權威 |
| `attachments.py` | 附件清單（資料夾結構同舊版） |
| `extractor.py` | 流程：登入 → 選票 → 等待開播 → 每張票一條串流 + 附件 |

- 帳密：`STREAMDL_ACCOUNT` / `STREAMDL_PASSWORD` 環境變數，或 `--account` / `--password`。
- 多視角：每張票各自登入一個 Session（舊版行為，避免同帳號共用 session 互踢）；未提供帳密時只能共用登入並警告。
- `--browser`：`auto`（預設，httpx 登入失敗才開瀏覽器）、`always`（每個視角以瀏覽器開啟直播間維持 session，等同舊版）、`never`。
- 下載中 401/403：重新載入直播間更新 cookies；登入失效則重新登入。瀏覽器模式改為重新整理瀏覽器並讀回 cookies。
- 輸入直播間網址時只下載該張票；輸入 detail 網址時依選票規則（直播中全部視角，否則最早開演的一組並等待）。
- 回溯關閉（`backfill=False`）。
